# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Marketing site for SBC US LLC (https://www.sbcusllc.com). Originally generated with Lovable (`.lovable/`), deployed on Vercel.

## Commands

```bash
npm run dev            # Vite dev server
npm run build          # client build + SSR bundle + prerender every route to static HTML in dist/
npm run preview        # serve the built dist/
npm run lint           # eslint (prettier runs as an eslint rule)
npm run format         # prettier --write .
npm run test:contrast  # WCAG AA contrast check on theme tokens (the only automated test; runs in CI)
npx tsc --noEmit       # typecheck — there is no npm script for it
```

There is no unit test framework. Both `bun.lock` and `package-lock.json` exist; npm is what the local `node_modules` was installed with.

## Architecture

- **SPA prerendered at build time.** Despite the `tanstack_start_ts` package name, this is plain Vite + `@tanstack/react-router` (`src/main.tsx` mounts `RouterProvider` with `createRoot`, not hydration). `npm run build` also bundles `src/entry-prerender.tsx` with `vite build --ssr` and runs `scripts/prerender.mjs`, which writes `dist/<route>.html` per route with that route's `head()` tags injected into `<head>` (marked `data-prerender`; `main.tsx` deletes them on boot so `<HeadContent />` owns the head client-side). `vercel.json` uses `cleanUrls` and has **no SPA rewrite**: unknown paths get `dist/404.html` with a real 404.
  - The route list lives in `entry-prerender.tsx` (static paths + `services` + `team` slugs). **A new route must be added there**, or it 404s on direct load in production.
  - Components must render without a DOM (no `window`/`document`/`localStorage` during render — only in effects or guarded), or the build fails.
  - `index.html` holds only tags shared by every page; per-page title/description/OG/canonical come only from route `head()` via `seoMeta()`.
- **File-based routing** in `src/routes/` via the `tanstackRouter` Vite plugin. `src/routeTree.gen.ts` is generated by the plugin on dev/build — never edit it by hand.
- **Services routes:** each of the six services has its own bespoke route file (`services.<slug>.tsx`) built from the shared pieces in `src/components/service/ServiceBits.tsx`. Literal routes take precedence over `services.$slug.tsx`, which is a data-driven fallback rendering from `src/data/services.ts`. When adding or renaming a service, update both the dedicated route and the `services` array (it drives the services index, home page listings and "Other services" links).
- **Team profiles:** `team.$slug.tsx` renders from `src/data/team.ts`; photos live in `public/team/`.
- **Every page wraps its content in `SiteShell`** (nav + footer); most use `Reveal` for scroll animations.

## SEO

SEO is a primary concern of this site; keep these in sync when content changes:

- `src/lib/seo.ts` — `seoMeta()` builds per-page meta/canonical links for a route's `head()`; `jsonLdScript()`, `breadcrumbJsonLd()`, `faqJsonLd()`, `organizationJsonLd` produce structured data. New routes should use these rather than hand-writing meta. JSON-LD that names the firm (`provider`, `worksFor`, `publisher`) uses `orgRef` so it links to the single `ORG_ID` entity. Pages with a visible `<FaqList items={…} />` must emit `faqJsonLd(sameItems)` so schema matches on-page text.
- `public/sitemap.xml` (hand-maintained `lastmod` dates), `public/robots.txt`, `public/llms.txt`, `public/llms-full.txt` — static, not generated. Add new routes to the sitemap and update the llms files when firm facts change.
- Brand naming: the canonical name is **SBC US LLC**. The aliases in `BRAND_ALIASES` (SBC USA, SBC US, SBCLLC US, SBCLLC USA, SBC LLC USA) appear deliberately in keywords, FAQs and JSON-LD `alternateName` for search coverage — don't remove them as "inconsistencies".
- `public/google35f45da451389ffd.html` is the Google Search Console verification file — don't delete.

## Styling

- Tailwind v4, configured entirely in `src/styles.css` (no `tailwind.config`). Colors are OKLCH CSS variables on `:root` / `.dark`, exposed through `@theme inline`. Custom utilities/classes such as `container-page`, `bg-gradient-ink`, `bg-gradient-warm`, `bg-gradient-soft`, `text-gradient-warm`, `icon-gem`, `shadow-soft`, `shadow-elevated` are defined there too.
- `scripts/check-contrast.mjs` parses token values out of `src/styles.css` with regexes and fails if listed foreground/background pairs drop below WCAG AA. If you change or rename tokens, run `npm run test:contrast`; tokens must stay in `oklch(...)` form for the parser.
- Dark mode is a `.dark` class on `<html>`, toggled in `SiteNav` and persisted in `localStorage("theme")`; an inline script in `index.html` applies it before first paint to avoid a flash. Light is the default.
- shadcn/ui (new-york style) components in `src/components/ui/`; icons are `lucide-react`. Import alias `@/*` → `src/*`.
- Prettier: double quotes, semicolons, trailing commas, `printWidth: 100`.
